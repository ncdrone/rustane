# K2 Deep Dive Audit — 2026-03-23

## Summary
4 parallel agents audited the entire inference codebase. Key findings below.

## Performance: K2 at 1.54 tok/s (12.4 ms/layer)

### Per-Layer Breakdown (estimated)
- MoE FFN total: ~8 ms (65%) — experts pread + Metal + shared FFN
- MLA attention: ~0.4 ms (3%) — 64 heads, half of V3's compute
- Conversion: ~2 ms (hidden by pipeline overlap)
- Other: ~2 ms (norms, routing, Metal overhead)

### Critical Path (serial, cannot overlap)
- MLA sgemv: 5ms (memory bandwidth limited)
- Metal dispatch: 3ms (XPC + ObjC overhead)
- = 8ms minimum = 2.05 tok/s ceiling on CPU path

## Bugs Fixed
1. lazy_mode threshold: `> 64` → `>= 64 || experts > 256` (K2 was using mmap)
2. Variable shadowing: shared FFN result lost in pread path (line 857)

## Top Opportunities (not yet tried)

### High Impact
1. **Wire ExpertPool** — 90% hit rate validated. Eliminates 90% of pread I/O.
2. **Metal backbone sgemv** — move MLA projections to GPU. Saves ~3-4ms/layer.
3. **Unified Metal command buffer** — all 8 experts + backbone in one dispatch. Saves ~2ms/layer.
4. **INT8 KV cache** — 4x memory reduction, frees RAM for expert pool.

### Medium Impact
5. **Batch W_UK/W_UV** — 8 sgemv → 1 sgemm_nt. Saves 0.66ms/token.
6. **Pre-allocate gate_logits + expert_ids** — eliminate per-token allocations.
7. **Tune sgemv_f16 chunk size** — 64 → 128 rows (better L2 utilization).

### Low Impact / Code Quality
8. Deduplicate expert_stride calculation
9. In-place RMSNorm
10. Batch lm_head with last Metal dispatch

## Three Compute Units
- CPU (AMX): 3 TFLOPS — handles MLA + shared FFN + conversion
- Metal GPU: 15 TFLOPS — handles expert INT4 dispatch ONLY
- ANE: 17.8 TFLOPS — COMPLETELY UNUSED

## Theoretical Max: 5.27 tok/s (all in RAM), 3.33 tok/s (90% expert pool)

## K2 vs V3 Advantage
- 64 heads = half MLA compute
- 23 GB backbone = 31% smaller
- Same expert routing (top-8)
- More headroom (91 GB available vs V3's ~50 GB)
